# 首次数据计算风险复现实验

日期：2026-11-05。状态：独立实验已验证，完整数据模块仍在调研。

## 范围与来源

使用项目自建合成订单，在内存 SQLite 执行 SQL。无真实商家或公司数据、无网络访问、无模型调用。此前的手工反例已写在模块研究中，本次固定输入并运行。

调研与候选方案见 [数据与指标研究](../research/001-data-and-metrics.md)。本实验比较直接求和、金额去重与订单身份去重，不构成 Wren 与自研语义层的完整对比。

## 环境与复现

实测环境：Python 3.9.6，SQLite 3.51.0；人民币分，UTC 统一时间格式，左闭右开区间。

```sh
python3 experiments/data-metrics/reproduce.py --output .local/probes/data-metrics.json
```

源代码和输入见 [实验目录](../../experiments/data-metrics/README.md)。首次正式结果为 [JSON 原始记录](data-metrics-2026-11-05.json)，包含 SQL、参数、输入与脚本 SHA-256、环境和全部观察值。

## 实际结果

| 场景 | 实际观察 | 判断 |
| --- | --- | --- |
| 两笔收款 100、80 元，一笔含两条明细 | 直接关联求和 280 元，正确值 180 元 | 关联扩大了订单粒度的金额 |
| 同一组样例使用金额 DISTINCT | 180 元 | 此样例碰巧正确，不能说明修复通用 |
| 增加另一笔 100 元订单 | 直接求和 380 元；金额 DISTINCT 180 元；按订单身份处理 280 元 | 手工正确值 280 元，金额去重漏掉另一笔订单 |
| 180 元收款的下一周退款 20 元 | 事件时间口径两周分别 180、-20 元；原付款批次截至期末累计净额 160 元 | 时间口径不同，回答不同问题，不能混用 |

9 个预先定义的观察值全部复现，包含错误算法预期的错误结果。不是 9 项产品功能验收，也不是模型准确率。

修正一次实验脚本中场景名称与期望键不一致的 KeyError 后，连续两次正式运行退出码均为 0，两份 JSON 字节一致。报告 SHA-256 为 `8380dd5747ed4f1ab2a2037d1259414846b961db842b5c601c9beea1ad2ddf93`。第一次脚本错误属于实验组织问题，不是被研究的 SQL 口径错误。

## 结论与局限

当前证据支持显式保存实体主键、关联粒度与指标时间口径，拒绝用金额去重作为通用修复。普通 SQL 和确定性校验已足够复现问题，无需让模型完成金额运算。

未覆盖商品金额分摊、取消与部分支付、多币种、重复事件等；尚未引入公开真实数据，也未评测模型、自然语言提问、数据接入或部署性能。是否需要完整语义引擎，仍需候选组件与最小数据契约的适配对比。

面试可复述的事实：发现一对多关联会放大金额，验证金额去重在同金额订单下失效，通过显式实体粒度得到可核查结果；这是合成数据上的工程实验，不是线上收益。
