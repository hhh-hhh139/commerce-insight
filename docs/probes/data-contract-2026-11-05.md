# 数据契约原型实测

日期：2026-11-05。范围：本地确定性工具，无模型、无 Java 服务、无线上用户。

## 问题、方案及基线

前一次 SQL 实验已复现关联后重复汇总、按金额去重误删与跨期口径差异。本次进一步验证：真实外部数据能否在明确映射下完成质量审查和两期比较，不让 Agent 直接面对没有业务含义约束的表。

需求先于实现记录于 [切片约定](../requirements/first-slice.md)。对标 Looker 和 Wren 的显式业务模型，选用有限数据契约作为验证基准，解析 Excel 复用 openpyxl。Wren 查询层选型仍待同输入适配实验，理由详见 [调研](../research/001-data-and-metrics.md)。

实施前可恢复快照：`.local/baselines/before-data-contract-20261105/source.tar.gz`，14 个源码／文档文件，各文件校验值位于同目录 `manifest.json`。归档 SHA-256：`74073151b2772dc7cb46fa727a91d8cf66544cddb238a83b5377dbb848235fd6`。不含 Git 元数据、原始外部数据或凭据。

## 实现范围

- `commerce_data`：CSV／XLSX 读取、显式映射确认、行校验、受控金额计算、两期与地区差异、能力限制和证据输出。
- 正向记录金额、取消记录金额及差额独立展示；采用 Decimal 保留原始小数精度。真实文件中存在分以下单价，不能先强制四舍五入到分。
- 字段转文本并去首尾空白后，全部源字段相同才标记为重复；单号相同或金额相同均不足以判断重复。保留策略不声称消除了数据质量问题。
- 空客户编码不影响金额汇总。非法行按原因隔离，报告数据子集范围；没有支付／退款流水时，相关能力请求由代码拒绝。
- 来源、映射和代码 SHA-256、指标版本、筛选范围、解析器及 Python 版本进入报告。源文件在读取前后再次校验。

## 固定样例验证

命令：`.venv/bin/python -m unittest discover -s tests -v`。

18 项测试通过，包含手工核算、同额单据、多明细粒度、重复策略、空值、第二套字段／状态／金额单位映射、分以下单价、日期边界、时区拒绝、零基数、缺失能力拒绝与 CSV／XLSX 等价读取。

第一次运行有 3 项失败：合成样例将一张正向单命名为 C，但 UCI 映射规定 C 前缀为取消，导致该行因状态和数量冲突被隔离。修正样例正向单号为 D 后全部通过，预先约定的金额未改变。这是样例语义错误，不是降低验收标准。

两套导出的预期值一致：第一期正向金额 50，第二期正向金额 30、取消金额 10、差额 20；正向金额变化 -20，变化率 -0.4。[合成输出](invoice-sample-2026-11-05.json)。这些测试都用于开发，不冒充独立保留集或模型成功率。

## 真实公开数据结果

来源及署名：Chen, D. (2015), [Online Retail, UCI](https://doi.org/10.24432/C5BW33)，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。以下是按本项目规则加工后的汇总，原始数据与许可记录见 [数据来源](../data-sources.md)。

| 检查项 | 实测 |
| --- | ---: |
| 输入行 | 541,909 |
| 当前规则可计算行 | 539,392 |
| 隔离行：非正单价或零数量 | 2,517 |
| 缺客户编码 | 135,080 |
| 缺描述 | 1,454 |
| 重复的后续行，按确认策略保留 | 5,268 |
| 全部可计算行的正向记录金额，GBP | 10,666,684.544 |
| 全部可计算行的取消记录金额，GBP | 896,812.49 |

按来源本地时间的半开区间比较 2011 年 10 月和 11 月：正向记录金额分别为 GBP 1,154,979.30 与 1,509,496.33，变化 GBP 354,517.03，变化率按六位小数为 0.306947。两个期间天数不同，未按日归一化。该金额含保留的重复行，并仅覆盖满足规则的记录，不是经过业务复核的净收入。

变化按国家／地区分解后加总与总差额一致。英国分组增加 GBP 386,371.20，部分其他地区下降抵消了增长；这只是算术贡献，不证明促销、季节或其他原因造成了变化。

主报告状态为 `requires_quality_review`。运行成功意味着完成计算及审查报告，**不等于源数据已经完全合格**。原始输出：[完整报告](uci-invoice-2026-11-05.json)。

## 独立核对与复现

`experiments/data-contract/verify_uci.py` 不调用核心规范化与汇总代码，使用 UCI 固定字段、按月有符号的百万分之一货币单位整数累加，核对总额、取消额、两期金额、行数与空值。12 项核对为 true，见 [独立输出](uci-independent-check-2026-11-05.json)。它仍共享 openpyxl 读取器，因此没有独立证明读取器对每个原始单元格的解析正确。

完整输入同环境运行两次，报告逐字节相同。SHA-256：`7ca3b20ca9e8b9498440a5394f4968eec4a8d3bd23864a30fdd09d185ec2f505`。第二份在 `.local/probes/uci-invoice-repeat.json`。环境为 Python 3.9.6、openpyxl 3.1.5、et-xmlfile 2.0.0、defusedxml 0.7.1，仅安装在项目 `.venv`；这是本地数据实验环境，不是未来 Agent 运行环境的最终选型。

复现命令见 [README](../../README.md)。读取全量数据及输出不访问模型或外部服务；首次下载与依赖安装需要访问 UCI／PyPI。原始数据、虚拟环境和缓存均已忽略，不进入 Git。

## 能说明什么，仍缺什么

可在面试中说明：先复现错误聚合，再参考成熟产品做显式业务语义；让数据契约限制模型可回答的问题；用两种输入格式及真实公开数据验证；数字带版本和证据；发现数据质量问题后明确给出限制。

还不能说：提升了 Agent 准确率、服务了真实商家、实现生产级退款分析或已经完成多 Agent 系统。当前没有自然语言解释、Java 任务链路、权限隔离服务、生产级上传沙箱或部署；也没有对 Wren 的运行效果作出优劣结论。
