# 单 Agent 接入与真实模型评测

日期：2026-11-06。结论：本地单 Agent 接入通过工程验收；固定小样本真实模型初验收达标，保留明确失败项。不是生产效果、真实商家收益或多 Agent 优势的证明。

## 研究、版本与输入

实施前 [研究记录](../research/004-single-agent.md) 和 [ADR 003](../adr/003-langgraph-single-agent.md) 比较了保持确定性 API、一次结构化提取、原生 SDK 循环、create_agent、手工 StateGraph 与更完整的 Agent 平台。

最终采用 LangChain 1.4.9 / LangGraph 1.2.20 / SQLite checkpointer 3.1.3 / LangChain DeepSeek 1.1.1，独立 Python 3.12.16 环境，完整 49 包哈希锁定。Java 21、Spring Boot 4.1.2、H2 2.4.240 继续使用本地单实例。确定性工具仍是 DuckDB 1.5.0；没有改原数据计算实现。

输入快照 SHA-256：`27048415cf67ccf74b818b62d046eb1d80eff6006e3966c8d7491bac25429cd4`。固定题集为 `experiments/single-agent/cases.json`：3 道开发题，7 道不同问题族保留题，各重复两轮。题集、提示词和业务计算真值在真实模型调用前已确定。预设门槛是保留集每轮至少 80%、已发布数字和引用的重算错误为 0。

[环境与实现清单](single-agent-environment-2026-11-06.json) 记录版本、JAR 和源文件 SHA。真实模型报告另记录每条任务的提示词、实现、框架版本、数据哈希与模型响应标识。

## 工程测试与实际修正

[首轮结果](single-agent-initial-2026-11-06.json)：41 项测试中 2 项错误，均为接入实现问题：

1. 工具参数被框架拒绝时，返回的是普通错误 ToolMessage，不能无条件当 JSON 证据解析。脚本化模型适配器与证据收集器均改为跳过错误消息，仅保留有效工具证据。越工作空间参数不能执行，但后续合法参数可以继续。
2. 图暂停后 structured_response 字段可能存在但为 null，不能仅检查字段存在。改为检查有效值，暂停后在新进程恢复时才继续生成最终决策。

早期 smoke 还发现结构化输出会附加工具消息；usage 统计只应取 AIMessage，否则会把正常最终输出误记为缺 usage。此问题在首轮完整验收前修正，原始 smoke 输出留在 `.local/single-agent/smoke-initial.log`。

修正后 41 项通过；追加 DeepSeek SDK 模拟 HTTP 协议检查，最终 [42/42 通过](single-agent-2026-11-06.json)，用时 27.198 秒。其中：

- 18 项原 Java/Python 任务闭环回归：并发领取、幂等、租约、取消、有限重试、Java/领取进程强制退出、冻结数据等。
- 19 项 Agent / budget / SDK 检查：实际 LangGraph 调用工具、错误后修正、未知工具拒绝、参数范围、伪造金额/引用、两期比较、零基期、数据不足、调用上限、跨进程 checkpoint 恢复/隔离、本地写锁、输入绑定、预算并发与未知响应、提供方请求格式与凭据不落入状态。
- 5 项新 HTTP 集成检查：Java agent 请求与报告、模型配置不可从请求注入、结果绑定/重复发布、取消后不发布、未配置个人 Key 不调用远程服务。

上述模型响应是脚本或 HTTP Mock，**真实外部模型调用为 0**。原有数据与口径测试另外 **46/46 通过**，用时 3.079 秒。构建日志、完整测试输出保存在项目 `.local/single-agent/`，没有使用全局 Maven/Java 配置。

## 真实 DeepSeek 结果

由用户在本地终端输入个人 Key，实际运行独立 Java → Python Worker → LangGraph → DeepSeek → DuckDB → Java 发布链路。Key 没有通过聊天提供，也不写入项目文件。模型请求名和响应标识均为 `deepseek-flash`；官方当日版本声明 DeepSeek-V4.1-Flash-1017，不将别名当成固定权重。关闭 thinking，temperature=0，单请求最多输出 1024 tokens，SDK 自动重试为 0。

开发集 3/3；保留集每轮 6/7，总计 **12/14 = 85.7%**。17 次业务任务都完成发布，技术状态 SUCCEEDED 不等于语义任务全部通过。全部 Java attempt=1，没有用业务重试提高本轮成功率。

严格保留两个 wrong_issue 失败，不修改题集、提示词、标签或阈值来制造满分。它们没有虚构利润，但“补数据即可继续”与“当前没有这项能力”给用户的下一步指引不同，属于需要优化的产品边界分类。后续应明确能力不足与数据不足的判据，并使用新的独立保留集验证，不能复用已看过的这道题作为新的泛化证明。

本轮只提供受控单 Agent 初始基线，未进行真实模型的一次提取、原生 SDK、多 Agent 架构对照，不能归因“LangGraph 提高了准确率”。两轮样本很小，不构成稳定性置信区间或真实需求证明。

## 当前限制

本地 H2 / SQLite 单实例、合成数据、有限指标与模板化报告；无公开用户认证、真实经营试用、完整前端、自由长文分析、生产部署或多机状态恢复。没有把 checkpoint 称为 exactly-once，网络不确定情况下仍可能重新调用模型。模型不能新增工具，也不能把用户指令当作权限。
