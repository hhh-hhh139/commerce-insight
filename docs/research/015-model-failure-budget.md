# 模型异常、重试和未知预算预占

日期：2026-11-08。源于真实验收失败，先修复工程可诊断性，暂不继续付费调用。

## 已观察事实

`scripts/evaluate_release.py` 首题 `dev_cohort` 的 Java 任务共领取 3 次：前两次执行器失败且没有 usage，第三次被共享预算拒绝。没有业务工具调用，三候选对照未开始。两次各预占 2105344 micro-CNY，账本累计 4525418；其中历史已收到用量的占用是 314730。新实际账单未知，不能写作“本次消费 4.21 元”。用户回复控制台没有异常，要求继续；这不是可核对的用量，也不授权清空账本。

已确认代码缺陷：SDK 原始异常只在 CLI 临时 stderr 中保留类型，被映射为可重试 `executor_failed`；临时目录随后删除，所以无法从当前证据恢复第一次异常究竟是鉴权、余额、格式还是连接问题。不得猜测 Key 错误或供应商故障。另有合并入口未捕获子套件 `SystemExit`，因此汇总缺少 `stop_reason`。

原始事实见 `../probes/context-live-incomplete-2026-11-08.json`。修改前源码为 `.local/baselines/after-context-engineering-20261108/source.tar.gz`，294 文件，SHA `da5973bd0fc5167a3a70108957982cf5370c3cde104ca45c0833fe01360f894e`，内容及成员已核验。

## 官方做法与选型

- [DeepSeek Error Codes](https://api-docs.deepseek.com/quick_start/error_codes/)（2026-11-08，滚动）：400/422 需修正请求、401 检查鉴权、402 检查余额、429 调整发送频率、500/503 可稍后重试。文档并没有给本次缺失响应提供计费结论。
- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)（同日）：checkpoint 保存执行状态、支持故障恢复，但不能证明外部付费副作用没有发生。本项目仍需持久化费用占用和错误审计。

方案 A 保持统一重试最省代码，但已导致连续未知预占，且没有可诊断信息。B 只给永久 HTTP 错误停止重试、暂时错误自动重试，适合余额充足且有请求幂等/计费核对能力的服务；本项目 5 元共享试验没有这些条件。选择 C：记录有限错误类别和状态码，保留预占；模型响应失败或已派发请求用量不明时不自动再发付费请求，人工查明后再决定。保留确定性工具与有完整 checkpoint/usage 的正常恢复。

错误日志不得含异常全文、请求头、响应 body 或 Key。本次旧未知预占不修改，不通过缩小估算、换文件名或新建预算绕过限制。合并入口明确记录子套件终止原因；没有对照结果即“证据不足”，默认保留单 Agent。

验收：模拟真实 SDK 401/402/422/429/503 与网络失败；断点后不重复请求；保留未知预算；预算拒绝单独标注为未派发；原断点恢复和 Java 任务测试回归。模拟 HTTP 结果不能补作本次真实失败原因。
