# 012 · 稳定性、资源边界与可观测性

日期：2026-11-06。状态：专项 12/12 已验证，见 [阶段 3a](../baselines/phase-03a-2026-11-06.md)。仅个人项目，合成数据、无模型费用。登录保护单独推进。

## 现状与问题

已有真实 JVM/H2/HTTP/Worker 测试验证幂等键、租约 fencing、重复发布、重试、取消和重启。代码审计发现：任务总数、排队数与并行租约数没有全局上限；Worker 虽有执行超时，Java 无任务绝对截止时间，持续心跳可无限延长租约；没有运行状态汇总。Worker 仅在执行完毕检查结果大小，执行过程中输出增长不受检测。销售和标量比较仍使用会产生负零的 Decimal 百分比，退款模块已经修复同类问题。

这些发现先用独立合成任务复现，再保存修复前结果；现有故障用例不会重复包装成新成果。新增限制是基于单实例资源边界的产品决策，不是已有真实过载事故。

## 决策与验收约定

- 默认保留最多 2000 个任务（含导入检查），活跃队列最多 32、有效执行租约最多 4；事务内锁定工作空间准入行，防止并发越限。幂等重放仍返回已有任务，不消耗新额度。
- 每个任务入队时持久化绝对截止时间，默认 15 分钟，重试/心跳不延长；后台扫描和关键操作均能终止过期任务，旧 Worker 不能发布。配置是单实例容量参数，不是性能测量结论。
- 历史不自动删除。总量上限使留存有明确边界；满额返回错误，保留备份/导出并由后续运维流程处理。导入归档不等于删除原始数据。
- 受保护状态接口只给状态计数、最老队列等待、最近拉取时间及限额，无问题原文、数据内容、凭据或高基数标签。这里是业务观测，非完整 APM。
- Worker 执行期间检查输出文件大小并终止越限进程；这只是受信任执行程序的失控保护，非任意恶意代码沙箱，也不声称绝对磁盘配额。
- 销售及标量百分比统一零的表示，保留精确差值，实际 Java 发布回归。
- 先记录并发超限、持续心跳、无 Worker 过期、输出增长和跨语言负零的修复前行为；再验证限额竞态、到期一次终止、重启保留截止、错误角色/工作空间拒绝及原任务/导入/分析回归。测试限额使用更小配置加速，单独记录，不冒充默认容量压力测试。
