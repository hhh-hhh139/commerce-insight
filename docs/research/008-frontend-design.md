## 问题与基线

## 备选方案与选择

1. 只换颜色和圆角：改动小，但长页和历史条件错误仍在。
2. 重建 React 应用并引入组件库：适合后续复杂状态和多人协作，当前会新增构建和迁移成本；现有两页和 API 规模暂不足以证明必要。
3. **重整现有 HTML/CSS/JS 信息结构**：分析、任务记录、历史样例分视图；导入页统一外壳；保留受限 API 与发布结果，仅修改显示和导航。选择此方案，零新增依赖、保持同源与现有 CSP。

重评框架的条件：增加多工作空间、多角色、多步骤编辑状态等，现有状态管理出现可复现维护问题时，单独比较迁移。

## 设计计划与审视

面向需要核查经营数字的运营人员；主要工作是选择已确认数据、设定口径、阅读变化并打开证据。

- 色彩：背景 `#F5F7FA`、表面 `#FFFFFF`、正文 `#243044`、操作蓝 `#3156D3`、增长 `#147D64`、下降 `#B34A3E`。颜色表达操作或数值方向，同时保留文字和正负号。
- 字体：本机 SF Pro Text / PingFang SC / Microsoft YaHei，中文长表单优先清晰；金额使用等宽数字特性。无第三方字体请求。
- 排版：左对齐；标题 24 px、正文 14 px、辅助 12 px；不使用全大写小标题、营销标语、渐变或装饰性动效。
- 记忆点：商品金额贡献条形图，来源为已发布报告，图形与明细互相核对。

```text
桌面：导航 | 页面标题
           | 条件（数据、口径、日期） | 报告（总额、贡献、明细、证据）
手机：带名称的导航 → 可折叠条件 → 报告；数据边界保留在可展开说明中
```

初始想法中的概览 KPI 大卡片和独立数据背景卡会重复信息，审视后移除。用真正的条件面板、贡献图和表格建立业务特征；首次使用显示待运行状态，不自动生成或冒充结果。没有后端支持的功能不做占位按钮。

## 预先约定的验证与后续

- 桌面、默认中等宽度和 390 px 手机断点检查导航、表单、表格与溢出；可见键盘焦点、语义名称和非颜色状态。
- 运行商品贡献，得到 280.00 → 150.00，P3 -100 / P2 -40 / P1 +10；展开证据并下载报告。空期间仍展示零值与“无商品”。
- 历史任务恢复实际数据和查询条件，浏览器前进/后退可恢复视图；历史模型报告保持明确历史标签。
- 验证导入、映射、质量检查、确认和转到分析；模型默认关闭及不允许模型的数据限制保持有效。
- 构建、网页 11 项工程验收及与改动相关的回归。数据、模型、Prompt、业务工具和依赖不改变；不以视觉改造声称模型准确率提升。
- 完成后记录源码差异、浏览器证据与局限，再推进新分析能力的评测准备；真实模型调用需要个人终端提供密钥，不能把离线脚本当真实模型效果。
