方案 A 保持完整上下文单 Agent，维护成本最低。B 精简单 Agent 可减少重复信息，新增证据保存与恢复校验成本。C 双专家隔离上下文，但重复提示词、更多请求和合并失败可能抵消收益。因此 A 仍是默认；B/C 只有达到下列预设条件才考虑采用。没有证据时保留实验，不为简历强行改名多 Agent。

## 实验协议（执行前固定）

- A/B 使用相同提示词、模型、数据、全部工具、最多 5 次模型 / 4 次业务工具调用；只改变工具返回上下文。C 两个顺序执行的专家，每个最多 2 次模型 / 2 次业务工具，总计最多 4 / 4，不宣称并行加速。每个专家看到原问题和自己的职责，工具集合的并集与 A/B 相同。顺序执行避免扩大并发预算预占。
- C 只在要求同时分析销售与退款的题集试验，两个结果均成功才合并；任何一边要求澄清或拒答均不发布“部分完成”的完整答案。合并由代码完成，不额外调用模型。不得将 C 的收益归因于动态调度。
- 同一版本 DeepSeek、非思考、temperature=0、输出上限 1024、SDK 零重试。按题和轮次轮换 A/B/C 顺序，保留时间和实际响应模型名。每项完整证据独立重算；不使用模型自评。
- 复合题 2 个开发题、6 个不同边界问题的保留题，保留各运行 2 次；开发题通过才打开对应候选保留集。开发/保留按业务边界拆分，题目仍是小型合成样本，不能声称统计显著或真实商家泛化。
- B 采用门槛：全部开发题通过；保留成功数不低于 A；零数字/引用审计错误；保留集实际总输入 token 比 A 至少少 20%；输出费不能使总保守费用增加。通过后仍须原三套题回归，无新增失败。
- C 采用门槛：全部开发题通过；12 次保留中至少比 A 多成功 2 次；零数字/引用审计错误；总费用与中位耗时均不超过 A 的 1.5 倍；不得新增原来 A 成功的边界失败。A 已接近满分时，C 即使全对也不能达到收益门槛，应放弃默认启用。
- 额度或外部故障造成不完整样本时结论为“证据不足”，不得只选择成功运行报结果。不更改阈值迎合结果。

## 工程验收与回退

实现级补充（编码前）：[LangChain Messages](https://docs.langchain.com/oss/python/langchain/messages) 的 `ToolMessage.artifact` 已支持程序可访问但不发送模型的数据。本地固定依赖的 `tool(response_format="content_and_artifact")` 也已确认支持。采用框架 artifact 随 SQLite checkpoint 持久化，不另外开发证据文件存储，也不新增模型可指定的路径。摘要证据损坏、丢失、跨快照均应拒绝；跨任务由现有 identity/目录隔离保证；中断恢复不丢完整证据，已完成重放不新增调用；模式/角色/限制变化不可复用旧 checkpoint。测试实际 provider 请求不含 artifact。保留原完整模式以便回退。测试脚本模型只证明控制和计算，绝不报告为真实模型成功率。
