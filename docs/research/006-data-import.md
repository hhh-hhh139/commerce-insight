# 外部账本 CSV 导入、质量检查与映射确认

日期：2026-11-06。开发前决策；实测结果在阶段 2d 单独记录。

## 当前断点与范围

现有网页只识别 `demo-ledger-v1`，Java 在创建任务时绑定启动时的固定快照；没有上传、映射、数据版本入口。早期单文件 CSV/XLSX 工具计算销售/取消记录金额，不能直接冒充订单支付或原订单退款。当前账本工具已经检查主键、金额、时区和关联，可以复用，不重写通用 ETL。

本版对象是可提供**订单表、商品明细表、可选退款表**的公开/合成 CSV；两套测试数据由已有样例派生，不宣称适配了任何国内平台官方导出。只有销售明细的 UCI 数据继续使用原契约，不能为了演示退款而补造支付状态。

## 调研（官方滚动文档，2026-11-06 查阅，未固定版本）

| 来源 | 文档支持的能力 | 借鉴与差异 |
| --- | --- | --- |
| [Metabase CSV uploads](https://www.metabase.com/docs/latest/exploration-and-organization/uploads) | CSV 上传产生表/模型，可追加或替换；类型推断可能失败；追加要求列名、顺序及类型一致 | 借鉴上传后模型管理；本版不追加覆盖，采用不可变版本。ID 保留字符串、金额显式单位，不从首批行猜类型 |
| [Wren MDL](https://docs.getwren.ai/oss/reference/mdl) | 模型声明字段、类型、主键与关系，可映射源列名，显式控制暴露的列 | 借鉴语义声明和关系核验，限定到已有账本契约；不实现任意表达式、自由 SQL 或通用语义引擎 |
| [Airbyte schema changes](https://docs.airbyte.com/platform/using-airbyte/schema-change-management) | 结构变化可自动传播或人工审查；破坏性变更暂停等待复核 | 借鉴版本绑定与确认门槛；修改映射后重新检查，旧确认失效。本版不是持续同步/CDC |

这些公开产品描述不能证明其内部实现，也不能替代我们的质量测试或用户价值验证。

## 比较与选型

1. 要求用户自行生成标准 JSON：代码最少，但把最容易出错的业务映射推给使用者，不能完成外部数据闭环。
2. 让 LLM 猜字段/状态并直接执行：能减少填写，但“销售额是否支付额”“退款成功时间是什么”不能仅凭名字证明。后续可加建议，本版不自动确认。
3. 接入完整 ETL/语义平台：连接器多，但当前仅三个文件和固定关系，新增部署、状态与依赖成本超过收益。
4. **采用有界 CSV 适配器 + 显式映射 + 既有校验 + Java 不可变版本**。Python 标准库 CSV/Decimal 负责解析，旧 `validate_snapshot` 保持业务最终校验；Java 管理原文件、检查版本、人工确认及任务绑定。

传输比较：multipart 更适合大文件/流式上传；本版每文件最多 128 KiB、最多三张表，使用 base64 JSON 保留原始字节及 SHA，复用当前 HTTP JSON 验证边界，不增加 multipart 临时文件生命周期。代价约 4/3 体积，不能扩容成大文件方案；扩大容量时须重评流式 multipart/对象存储与独立资源池。

执行比较：Java 直接启动 Python 子进程容易形成第二套超时/重试逻辑；额外 Python HTTP 服务增加部署面。采用原持久任务队列的 `import_check` 类型，复用租约、重试、取消、结果 fencing；解析仅生成质量结果，不调用模型。结构预览和映射验证都走同一执行路径。

## 状态与正确性约束

上传源文件不可修改 → 结构预览任务 → 选择字段、状态、单位、时间基准 → 创建映射检查修订 → 展示检查与能力 → 确认指定修订/检查摘要 → READY 数据版本。每次修改映射创建新检查；确认必须匹配最新 revision、任务 ID 和 review SHA。确认后的版本不能修改，再上传形成另一版本。归档禁止新查询，已创建任务保留自己的快照。

金额以 Decimal 严格换算为整数分，不舍入多余精度；标识符不转数字；时间必须有偏移或明确选择 UTC / UTC+08:00 固定偏移。列映射与状态映射均为有限字段，无脚本/表达式/路径/URL。

行级解析收集错误计数与前 50 个定位信息，不发布原始值到日志；主键重复是错误，不做去重。任何错误都阻止整批发布，没有“丢弃坏行后当完整结果”。跨表业务校验复用已有契约，当前报告首个关联层错误，不能称为列尽全部质量问题。

无退款文件不等于退款为零，只开放支付相关指标；成功退款缺商品归属时，商品退款能力标为受限（本版保守禁用该数据版本的商品退款查询）。原指标执行器仍独立校验，不依赖页面按钮。

## 边界与数据管理

只在个人项目运行，界面要求声明公开/合成且无敏感内容；不访问公司数据。继承本机 Demo 的严格回环/同源边界，不声称已有多用户认证。新上传文件仅保存在项目 ignored H2；不写入 Git、公开评测或第三方服务。源文件名只作为显示元数据，不作为路径。

默认模型使用许可为 false；确认时可显式允许该版本用于个人模型。Java 对 Agent 创建任务检查许可；实时模型还须个人终端显式启用。当前验证只使用合成文件与离线模型，零新增真实模型调用。

最多 50 次导入/工作空间（归档仍计数），每次导入最多 20 次映射检查；每表 2000 行、40 列、每格 4096 字符，规范快照最多 1 MB。原文件、映射与质量报告保留供审计；归档不是物理删除，当前不提供自动清理和大规模保留策略。生产身份、配额、多租户、删除与审计保留策略需后续独立实现。

## 实施前验收

- 两套列名/状态/元分单位/时间表示不同的 CSV，经明确映射得到相同规范表及 23000 分 cohort_net。
- 导致精度或金额对账冲突的元分误配、超精度、重复主键、混币种、孤立关联、金额不平、未知状态、非法时间、文件/行数边界均阻止发布；错误可定位且无静默丢行。所有表一致但错误的单位/状态/时间声明可能通过结构与对账约束，检查不能替代人工语义确认，也不能证明源文件完整。
- 确认前不能分析；旧修订/伪造摘要不能确认；重复确认幂等；确认后的映射不可修改；重启保留版本与报告。
- 无退款表只开放支付能力；缺商品归属不开放商品退款；调用者绕过前端也被拒。
- 老任务冻结数据，上传/归档其他版本不改变旧报告；未允许模型的数据版本不能创建 Agent 任务；离线 LangGraph 可复用已确认版本。
- 上传→预览→映射→检查→确认→选择数据→查询在浏览器走通；原数据、Agent、网页检查按变更范围回归。

前端本阶段只完成必要流程。用户已明确当前视觉不满意：完整功能闭环稳定后，另做真实应用的整体视觉与交互重构，不能把当前页面当最终设计交付。
