# 011 · 报表差异核对

日期：2026-11-06。状态：工程与网页已验证，见 [阶段 2j](../baselines/phase-02j-2026-11-06.md)。输入范围为有限指标的结构化报表；公开或合成样例，不接入支付账户。当前是确定性表单入口，没有新增模型调用。

## 当前问题与基线

用户拿到两份报表时，数字差异可能来自定义、时间、状态、粒度或版本，而非计算错误。现有系统能分别算指标，但普通标量比较正确拒绝不同口径，无法核对外部报告声明的数值。

[基线复现](../probes/reconciliation-before-2026-11-06.json)：同一支付批次的已支付金额 28000 分，扣除截至 10/19 的退款后为 23000 分；差异 -5000 分可解释。若外部第二份报告写 24000 分，观察差额为 -4000 分，仍有 +1000 分差异待核查，不能因为发现“退款口径不同”就宣称全部解释。

## 方案选择

1. 只比较报表总额或让模型阅读两张图：快，但缺少可验证口径与原始数据；容易把猜测当解释，不选。
2. 接入通用电子表格/BI/支付对账平台：可覆盖更多格式，需额外数据连接、配置和部署，超出当前可验证业务范围；后续连接器再评估。
3. **结构化报告声明＋选定已授权快照重算＋显式差异与残差**：采用。复用现有任务、数据版本、指标查询、归档与证据链，无须新调度系统或新 Agent。固定格式是首版代价；缺少必要业务元数据的任意 CSV/截图不自动推断。

## 输入与信任边界

两份 `commerce-report-claim-v1` JSON，或从本系统已下载的单指标任务报告提取声明。每份声明含名称、指标查询、声明值、币种、最小单位精度、结果单位、指标版本及源数据 SHA（不知道时显式 null）。界面预览后必须人工确认，再建立不可变核对任务。上传报告是待核查数据，哈希不是可信签名；任何 SQL、网页指令或模型文字都不执行。

两份声明均针对用户选定的一个授权快照核查。若源版本未知或不一致，只列版本问题与该快照的参考计算，不声称重建其他版本；后续跨快照逐行变更核对是独立扩展。指标仅接受现有八个标量，结构化商品/退款分析不能假装单值报告。缺退款表、缺商品归属、币种/单位不一致或未知指标版本均保留明确待核对项。

## 输出逻辑

- 左右报告分别展示声明值、重算值、声明减重算的偏差，防止“两边同错同量、差额却为零”被当成匹配。
- 展示指标定义、期间、退款截止、商品范围、单位、源版本，以及由指标目录确定的事件时间/状态/粒度差异。
- 只有双方可验证且单位/币种一致时，提供金额桥接：左声明值 → 消除左报告偏差 → 受控口径/筛选重算差异 → 加入右报告偏差 → 右声明值。各段与最终差额严格相等；报告自身偏差属于待核查，不冒充业务原因。
- 同期间支付额与批次净额差异可说明为退款扣除；其他多条件同时变化，只标为联合口径/筛选差异，不捏造各因素独立贡献。
- 输出 `matched`（口径与金额均一致）、`explained`（声明与重算一致且有口径差异）、`discrepancy`（至少一份声明偏离重算）、`needs_review`（缺少来源/定义/可比单位或数据）。不能只看两个总额相同。
- 数字、差异说明和报告文字由代码生成；未来 Agent 可基于已固定的报告上下文选择该工具，不能自行生成“上传报告”的数值。

## 预先约定的验收

28000→23000 分的口径差异可解释；28000→24000 分须保留右侧 +1000 分偏差；两份同错同量也须发现；相同时刻不同 ISO offset 不制造时间差异；跨币种/单位不做算术桥接；未知来源/版本/缺表不宣称验证成功；上传字段/确认/大小/非法数值受限；完整任务/历史/取消/重启/伪造结果拒绝与浏览器操作验收。新框架不是目标，可追溯的核对结果才是目标。
