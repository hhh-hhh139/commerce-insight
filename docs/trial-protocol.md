# 首次独立试用与反馈记录

状态：试用方案，尚未招募或执行。没有填写虚构用户、完成率或经营收益。

## 要验证的假设

目标人群是能导出账本、需要反复核对销售和退款的商家或运营人员。先验证三件事：能否理解字段与口径确认，能否从报告找到可核查数字，是否愿意在下一次同类任务中再次使用。求职者或同学可以发现易用性问题，但不能代替商家需求证据。

没有真实账本时，使用仓库公开合成样例完成以下任务。记录是否独立完成、耗时、求助次数与具体卡点；主持人不提前讲解正确答案。如果参与者先看过答案，则标记为已知答案练习，不计入独立完成统计。

| 任务 | 观察点 | 主持人核对依据 |
| --- | --- | --- |
| 导入一套不同列名的合成 CSV 并确认口径 | 能否区别金额单位、状态和时间；能否定位质量错误 | 对应导入 fixture 与确定性测试结果 |
| 比较两期销售并指出影响最大的商品 | 能否找到数据版本、贡献合计和其他项；是否误读为因果 | 2026-10-05 至 12 对比 12 至 19：280→150 元，P3 −100、P2 −40、P1 +10 |
| 解释退款商品归属不完整 | 是否注意到未归属金额，而非只读排名 | 2026-10-12 至 19 的 50 元退款中，30 元已归属、20 元未归属 |
| 核对两份口径不同的结构化声明 | 能否区分口径差异、数值偏差与证据不足 | 使用报表核对测试 fixture，先由主持人重算 |
| 找回历史报告、导出并退出 | 能否恢复相同数据版本；退出后旧页面不能继续操作 | 历史版本不变与会话失效 |

模型任务须单独获得数据发送许可与测试预算；没有这两个条件就使用确定性入口，不将离线演示记录为自然语言成功率。试用环境由参与者自己部署或明确授权，不能让其向公开 issue 上传真实账本、订单、截图中的客户信息、完整日志或凭据。

## 每次试用记录模板

- 日期／匿名参与者编号／角色／是否有实际同类工作：
- 版本 commit／运行模式（确定性或真实模型）／数据样例版本：
- 是否提前了解操作和答案／主持人提供了哪些帮助：
- 每项任务：独立完成、协助完成或未完成；开始/结束时间；求助次数；阻塞位置：
- 用户认为结论支持什么行动；是否错误推断因果：
- 过去如何完成同类工作；使用频率；最想保留与最不需要的功能：
- 是否愿意再次使用；原因；愿意尝试的下一次具体任务：
- 可公开的脱敏反馈／仅本地保留的敏感内容：
- 对应问题编号、修复版本、复测结果：

汇总时同时报告人数、任务数、参与者背景和失败；不同数据/模式分开。不以“觉得有用”换算节省工时，不把同学完成样例等同于真实商家留存。只有获得同一任务的旧流程基线和重复测量后，才讨论效率改善。
