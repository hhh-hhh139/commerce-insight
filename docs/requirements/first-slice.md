# 第一个可运行切片：导入数据并核对销售变化

日期：2026-11-05。这是首阶段需求与验收约定，不代表完整产品已完成。

## 用户实际完成什么任务

假设用户是能导出销售明细、但需要反复手工核算的电商运营人员。第一次使用时，先导入文件、确认字段和口径，再回答：**两个指定期间的记录销售额相差多少，变化集中在哪些国家／地区？**

完整应用后续由 Java 管理数据版本、授权与任务，Python LangGraph 调用分析工具并组织解释。本切片先提供本地 CLI 和确定性工具，验证它们以后交给 Agent 使用是否可靠。自然语言交互、页面和服务通信尚未实现。

## 本次输入及业务边界

- 接收 CSV 或指定工作表的 XLSX；最小粒度为一条销售／取消明细，不要求文件名或列名固定。
- 必需字段：记录单号、商品／条目编码、数量、单价、事件时间。国家／地区、客户编码、描述可选。
- 映射必须声明币种、单价单位、时间含义、状态规则、重复行策略，并由调用者显式确认。未知映射不自动猜测。
- 先支持单文件、单币种、来源本地时间。时间没有时区信息时保留其含义，不擅自变成 UTC，也不提供跨时区合并。
- 采用 UCI Online Retail 作为首个真实公开输入。其 `InvoiceNo` 的 C 前缀表示取消；它没有支付流水及原订单退款关联。订单主表＋明细表适配和退款流水契约仍是后续独立交付。

## 输出与验收

| 用户需求 | 本次可检查的输出 | 验收条件 |
| --- | --- | --- |
| 知道导入文件是否可用 | 总行数、空值、重复行、无效行及原因 | 坏数据不能静默消失；有效行＋隔离行＝输入行 |
| 知道统计的究竟是什么 | 币种、单位、状态、时间、重复行策略、能力清单 | 无支付、成本、退款关联时明确不支持对应指标 |
| 数字可核算 | 正向记录金额、取消记录金额、两者差额 | 使用十进制；不把单号当明细唯一键，不按金额去重 |
| 比较两个期间 | 半开区间总额、差额、国家／地区分组差额 | 分组差额加总等于总差额；前期为零时不生成无穷增长率 |
| 更换同类导出格式 | 另一份列名、状态编码、金额单位不同的合成 CSV | 只换映射，得到相同业务数值；不修改核心逻辑 |
| 复查结果 | 文件、映射、指标及代码版本，筛选参数和计算结果 | 相同输入在相同环境下重复运行输出一致 |

精确定义：正向记录为 `sale` 且数量、单价均大于零；取消记录为 `cancellation` 且数量小于零、单价大于零。金额为数量乘单价及映射中的单位换算系数；取消金额展示为正数，差额为正向金额减取消金额。计算保留来源十进制精度，不先把单价舍入到分。异常状态、非数值、零／负单价等隔离并报告；不宣称隔离后的数据代表完整经营事实。

同一单号多行是正常情况。完全重复的源行只能提示，无法凭文件判断是重复导出还是两条真实明细；默认明确选择保留并标记，也允许拒绝整批。缺客户编码不影响销售汇总，不因此丢弃记录。国家／地区缺失单独归入未知分组。金额可能含邮费等条目，暂不称为商品 GMV。

## 实施前固定的检查

合成开发样例：第一期两张单，A 含 2×10 和 1×5，B 含 1×25，共 50；第二期 D 为 3×10，同时取消 A 的 1×10，共正向 30、取消 10、差额 20。正向金额变化为 -20，变化率 -0.4。最初将第二期正向单命名为 C，与 UCI 的取消前缀冲突，首次测试暴露后改为 D，期望金额未变。

另设计算边界：重复行保留／拒绝、两张同额单、空客户、缺必需列、未知状态、单位换算、小数单价 0.001、日期区间边界、带时区时间拒绝、前期为零、缺退款能力拒绝。它们是确定性工程测试，均用于开发，不冒充独立模型保留集。

真实公开文件的总额不预填答案。先分析全文件，核验行数守恒及分组守恒；再独立用另一种累计路径核对关键金额。该结果只证明指定口径下的计算可复现，不证明运营价值或因果解释正确。

## 本次方案取舍

1. 直接让模型读字段和写 SQL：不能证明口径正确，保留为后续受控对照。
2. 显式映射＋有限确定性指标：当前用于验证数据质量和计算基准；输入输出可替换，不自研通用语义 SQL 规划。
3. Wren：当前文档已提供 MDL、查询规划、LangGraph 工具集，是后续查询层候选。即使采用它，仍要确定源数据业务含义及质量处理规则。本次不将数据适配器试验冒充 B/C 查询引擎性能对比。

依据与待验证项见 [模块调研](../research/001-data-and-metrics.md)。首个适配器通过不等于阶段 1 全部通过；Wren 同输入适配、多表订单与退款契约仍需完成。
