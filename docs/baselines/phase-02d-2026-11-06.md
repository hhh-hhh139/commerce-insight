# 阶段 2d：外部数据、质量检查与映射确认

日期：2026-11-06。状态：有界账本 CSV 本机导入闭环已实施并验证；通用连接器、真实私有数据、生产部署与真实用户试用未完成。

## 问题、比较与结果

阶段 2c 的网页只能使用内置 `demo-ledger-v1`，用户不能上传自己的同类数据；旧单文件销售/取消工具也不能直接作为支付/退款数据使用。该断点已在开发前源码与页面中确认，不虚构错误金额作为“优化前表现”。

参考 Metabase 上传模型、Wren 显式语义模型、Airbyte 结构变更审查后，比较标准 JSON、模型自动猜测、完整 ETL 平台和有界适配器。最终采用**显式 CSV 映射、确定性检查、人工确认、不可变数据版本**，复用原 Worker 任务闭环而不新增另一套 Python 服务/调度。详细依据、官方来源及日期见 [006 研究记录](../research/006-data-import.md)。

| 维度 | 阶段 2c | 阶段 2d |
| --- | --- | --- |
| 网页数据入口 | 内置合成 JSON | 上传订单、明细、可选退款 CSV；已确认数据版本可选 |
| 字段与口径 | 预先规范化 | 显式列、状态、元分、单币种与时区映射；同名列仅预填建议 |
| 质量反馈 | 分析任务失败时查看 | 先看结构，再做逐行/关联/金额检查；有错误整批禁止发布 |
| 允许分析的时机 | 固定已审查样例 | 最新检查通过且用户确认 revision、任务和摘要 |
| 数据能力 | 执行时契约检查 | 版本能力声明 + Java 入口 + Agent 工具 + 原执行器校验 |
| 历史复现 | 固定样例快照 | 每个任务冻结已确认数据；新上传或归档不改旧报告 |
| 模型使用 | 本机模式显式开启 | 还需逐数据版本允许，默认仅本机计算 |
| 交互 | 查询与报告 | 增加导入、映射、质量、确认和归档；视觉仍为临时功能界面 |

- Maven 构建成功。导入验收 **25/25**，14.083 秒，含 12 个适配器和 13 个真实 JVM/H2/Worker/HTTP/离线 LangGraph 测试：[结果](../probes/data-import-2026-11-06.json)。整套耗时包含启停，不是接口性能指标。
- 原 Agent/任务 **42/42**，原网页 **11/11**，全数据 **58/58** 回归通过：[Agent](../probes/data-import-agent-regression-2026-11-06.json)、[网页](../probes/data-import-web-regression-2026-11-06.json)、[数据](../probes/data-import-data-regression-2026-11-06.json)。58 项包含与导入套件重复的 12 项，不能重复计数。
- 英文列名/分/带偏移与中文列名/元/UTC+08 两套 CSV，经各自映射生成相同业务表，查询均为 **23000 分**。原文件与版本 SHA 不同，不能把“业务答案相同”写为“文件相同”。
- 修改另一次上传中 A 订单与 A1 明细金额，新版本结果 **24000 分**；旧报告逐字段不变，旧版本再次查询仍为 **23000 分**。归档后的排队任务仍按已冻结快照完成；重启后报告和归档状态保留。
- 确认前查询、旧 revision、错误摘要、错误结果输入 SHA、未确认模型许可、无退款表的净额查询、缺归属的商品退款都被拒绝；并发重复确认仅产生同一版本。
- 即使模型脚本直接请求受限退款工具，也返回 `dataset_metric_unavailable`，不生成数字证据。用非秘密哨兵验证 import_check 子进程不继承个人模型 Key。
- 浏览器实际上传中文样例：导入 `2984ba8e-6ddc-4532-a8fa-650da132a961`，修改映射使确认失效，重新检查后确认修订 2；页面、刷新及服务重启均保留已确认状态。分析任务 `62f4a7f4-da39-4657-9c99-fa5295612a8d` 返回 **230.00 CNY**，可查看 SQL/参数/来源并下载报告。控制台错误/警告查询为空。详见 [浏览器记录](../probes/data-import-browser-2026-11-06.json)。
- **本阶段新增真实模型请求 0 次**；既有总调用仍为 35、保守费用上界仍为 0.137988 元。新增数据的图接入和权限测试使用脚本模型，不能宣称真实 DeepSeek 在新导入数据上的质量已验收。

## 失败与修正

首轮 21 项检查中 8 项上传失败：ImportService 直接读取被 Spring 代理的 Repository 实例字段，字段为 null。修为正常构造器注入 JdbcTemplate，并将仓库字段改为 private。保留 [首轮失败](../probes/data-import-initial-2026-11-06.json) 与 [21 项修复后记录](../probes/data-import-second-2026-11-06.json)，之后补充四项边界得到最终 25 项通过。

浏览器发现确认完成后质量区仍写“再确认数据版本”，已改为已确认状态并复查。未借此进行整体视觉改版。

## 当前限制与后续方向

1. CSV 只适配现有账本语义，每文件 128 KiB / 2000 行；样例是合成数据，并非某个国内平台导出认证。UCI 销售/取消数据仍属另一契约，不能硬映射为支付和退款。
2. 质量检查能发现格式、关系和金额约束冲突，不能证明源数据完整、语义正确。例如所有表一致填错元分单位，仍可能满足对账规则；因此保留人工确认。跨表层只返回首个错误，未做通用清洗。
3. 归档保留原数据、计入 50 次导入上限；暂不支持物理删除、自动保留策略、大文件隔离资源池和多用户生产权限。当前只允许公开/合成数据在本机使用。
4. 外部数据真实模型评测、扩大独立保留集、澄清/拒答分类优化仍待完成。接下来先定义一组能从导入到结论完成的经营任务，再按同一规则调研“销售变化的分组贡献、退款变化定位”，用对照样本验证工具能力与单 Agent 表现。
5. 生产认证/数据库迁移、干净环境容器化、部署和试用继续单独验收。**用户已明确当前前端不满意：功能闭环完成后再整体重构视觉、信息层级与交互，做成正式应用；当前界面不是最终设计。** 多 Agent 仍需与强单 Agent 对照后决定。

## 面试复述

“原演示只跑固定快照，我补了外部账本数据接入。调研 Metabase、Wren 和 Airbyte 后，没有让模型凭字段名决定财务口径，而是用有界 CSV 适配器、显式状态/单位/时区映射和人工确认。Java 管版本和确认事务，Python 复用原任务队列做校验，确认后冻结快照给原 LangGraph 和 DuckDB。两套格式得到相同 230 元，新数据变化不影响旧报告；25 项导入检查覆盖幂等、旧版本确认、能力约束和重启。现在是合成数据的本机工程验证，尚未宣称真实商家收益或生产上线。”
