# 阶段 2g：商品贡献评测准备

日期：2026-11-06。状态：评测器工程验证完成，**新的真实模型验收待运行**。这是阶段 2f 前端改造之后接续的下一项工作。

## 问题、选择与实施

旧评分器直接读取标量 `value`，商品贡献报告没有该字段；旧重算只会执行标量查询。[实际复现](../probes/sales-evaluation-before-2026-11-06.json) 记录正确 -13000 分被 `KeyError` 中断。参照 LangSmith 的代码评分、Ragas 的工具参数与结果分开评价，选择扩展现有评测器，详见 [调研与取舍](../research/009-sales-evaluation.md)。

修改 `scripts/evaluate_personal_agent.py`：新增结构化期望值评分、按结果类型重算、严格 JSON 类型对比；增加 `--suite sales-change` 选择固定新题集，新结果指针与旧实验分离。没有改 Agent 模型、Prompt、工具、Java 服务、网页或依赖。

预先固定开发集 3 题、保留集 6 题各两轮，每轮至少 80%，发布数字/引用错误为 0。详情、限制和运行命令见 [专项评测说明](../../experiments/sales-evaluation/README.md)。这些题目数量不是已完成真实评测数量。

## 实测结果

- 旧实现：脚本模型生成正确结构化结果，评分抛 `KeyError: value`，发布审计失败。
- 首轮新检查：11 项中 1 项失败。Python 原生相等比较把 `False` 与 `0` 当作相等，重算没有发现错误类型。保留 [失败记录](../probes/sales-evaluation-initial-2026-11-06.json)。
- 修正为规范化 JSON 摘要比较后：**11/11**，2.270 秒，[原始结果](../probes/sales-evaluation-engineering-2026-11-06.json)。涵盖 9 道新题、10 道原题的手工预期与脚本报告重算，以及篡改/边界反例，不把这些子案例叠加宣称更多独立测试。
- 所有脚本报告均被真实模型评分入口判为 `not_a_real_model_run`。未产生新的模型请求，真实效果仍未测量。
- 本轮结束前个人累计账本仍为原 **35 次请求、保守费用上界 0.137988 CNY**，不是新增消费，也不是平台实际账单。新旧实验继续共用 5 元总上限；重新核对当日官方价格后没有修改费率。
- 用户需在个人终端输入 Key 后才能执行真实评测；已提供具体命令，尚未收到新的运行完成信息。既有模型报告不能替代新能力验收。

源码归档：`.local/baselines/before-sales-evaluation-20261106/` 与 `after-sales-evaluation-20261106/`，均有 SHA 清单；[源码审计](../probes/sales-evaluation-source-audit-2026-11-06.json) 记录变更边界。没有触碰公司仓库/服务、GitHub 远程、全局配置或公司凭据。

## 可复述的工程收获

新增业务工具后，不仅要验证工具自身，还要检查评测器能否正确评价新输出类型。这里先复现评分器失败，再保留老题兼容、增加结构化期望和重算审计；用篡改反例验证评分不会误放行。最后把脚本工程检查与真实模型质量严格分开，等待新模型实验得到可引用的实际成功率与失败类型。
