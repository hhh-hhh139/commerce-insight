# 阶段 4b：真实验收中断与模型故障处理

日期：2026-11-08。真实模型验收未完成；故障处理工程已验证。没有调整预算上限、释放未知占用或切换默认分析流程。

## 实际发生了什么

用户运行合并入口，原指标首题 `dev_cohort` 的 Java 任务经历三次领取。前两次模型调用尝试没有收到可结算的 usage，第三次被预算保护拒绝；没有业务工具调用。旧版本只留下 `executor_failed`，异常类别在临时目录删除时丢失，所以无法确定请求是否到达服务商、真实失败原因或实际扣款。

这不是三种 Agent 架构的效果结论：销售、退款回归及架构对照均未运行。用户表示控制台没有异常、继续开发；未提供可对应到请求的用量，因此两项预占继续保留。原始证据见 [未完成验收记录](../probes/context-live-incomplete-2026-11-08.json)。

共享账本现在共 67 项：历史 65 项已收到 usage，保守占用 0.314730 元；新增两项各未知预占 2.105344 元，合计账本占用 **4.525418 元**。该数值不是实际账单。当前无法预占新的完整请求，后续付费评测待核对，不能删除旧账本或新开 5 元。

## 为什么这样修复

[研究 015](../research/015-model-failure-budget.md) 比较统一重试、按状态重试和未知费用停止自动调用。对本项目的固定小额预算，采用后者：保存有限错误码、HTTP 状态、异常类；不存异常文本、响应 body 或请求头。401/402/400/422/429/500/503 和连接错误各有明确分类。模型异常变为非自动重试；已派发但未确认用量的图节点也不盲目重放。普通确定性任务与有已确认 usage 的 checkpoint 仍可恢复。

预算准入拒绝明确记为 `provider_dispatched=false`，不会冒充一个服务商请求。合并入口在未知预占存在时停止后续题，捕获子套件 `SystemExit` 并记录阶段及终止原因。界面显示相应中文提示。旧两项预占完全不修改。
