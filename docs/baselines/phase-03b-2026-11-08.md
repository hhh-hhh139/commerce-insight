# 阶段 3b · 单店主登录与会话控制

状态：单店主模式、原本地模式回归与实际浏览器闭环已验证。研究/首轮实施在 11 月 6 日，跨时段浏览器检查与最终专项在 11 月 8 日；不将日期混写成一次连续执行。公网 TLS、部署资源与真实试用仍待后续验证。

## 变化及选型

原入口是严格限制回环的免登录 Demo，不具备公网身份能力；[基线](../probes/owner-access-before-2026-11-06.json)显示本地匿名配置访问 200、登录页不存在、外国 Host 被拒。它是刻意的本地模式，不是公网泄漏事故。

新模式明确启用 owner 后，用 Spring Security 7.1.2（Spring Boot 4.1.2 管理）负责表单认证、会话更换、退出和 CSRF；部署者通过自己的终端设置应用密码，运行目录仅存 BCrypt cost 12 哈希。网页登录不携带服务 bearer。采用单店主、单空间的真实边界；未实现注册、邀请、组织角色或多租户。方案比较见 [013](../research/013-owner-access.md)，运行见 [说明](../../experiments/owner-access/README.md)。

配置唯一 Origin、Host 与 HTTPS Secure-cookie 条件，不信任代理身份头。内部服务接口仍区分 user/worker bearer，新增 owner 模式的回环 Host/来源限制。默认每进程 10 次登录尝试/分钟；这是有限状态的基本保护，重启重置，不声称分布式攻击防护。会话在内存，重启需登录；业务任务/报告持久化。

[首轮](../probes/owner-access-first-2026-11-06.json) 5 失败、1 错误：5 项都提前停在默认成功/失败重定向生成内部绝对 HTTP URL。现采用固定相对路径，避免未来 HTTPS 代理后跳到内部 HTTP；这项收益是配置推断，真实 TLS 尚未测。另一个错误由测试器重复传入同名 Spring 参数造成，已改为唯一键，不包装成产品缺陷。[第二轮](../probes/owner-access-second-2026-11-06.json) 8/8。

实际长时间停留的导入页发生会话过期，旧 CSRF 令牌提交时得到通用 `session_request_rejected`，用户不能理解下一步；[反例](../probes/owner-session-expired-before-2026-11-08.json)和截图保留。修复后，未登录工作台请求返回 401 并进入 `/login?expired`，已登录但 CSRF 错误仍为 403。另一标签退出后，旧页提交正确跳转且说明需重新选择未提交文件；没有自动重试写操作。

浏览器使用临时合成账户，未使用个人真实密码/API Key。测试服务停止后移除该专用 QA 目录的测试密码哈希，保留测试任务、数据和截图；没有改动用户默认 owner 目录。额外测试标签页已关闭，视口已恢复，最终日志中无 warn/error。
