## 发现与修正

1. 首轮新增测试 10 项出现 2 个清理错误：测试结束后对 SUCCEEDED/FAILED 任务再次取消，服务正确返回 409。修正测试清理为仅取消 QUEUED/RUNNING，保留 [首轮记录](../probes/web-demo-initial-2026-11-06.json)。这不是服务缺陷，也不是删除失败来提高正确率。
2. 启动器停止后立即重启，端口预检查受 TIME_WAIT 影响，误报占用。为预检查 socket 开启 SO_REUSEADDR 后成功重启；不会抢占活动监听或结束未知进程。
3. 原始评测错误 `wrong_issue` 在用户页面直接暴露实现代码，改为“拒答原因分类不符合预期”；原 JSON 未改。

## 尚未完成与下一步

1. 网页实时模式接受任务已离线验证，但尚未从新网页发起新一轮真实模型调用；已有历史真模型结果不能替代该项。只在用户个人终端启用后按同一共享账本验证。
2. **优先建设外部数据接入闭环**：上传/选择 → 版本与质量报告 → 字段/状态映射确认 → 能力限制 → 同一问题查询。先调研 Wren/Metabase 等公开实现与实际电商导出样例，建立两套外部字段结构的对照；不能把规范化快照当作任意平台原始文件。
3. 接入界面前明确数据大小、暂存与清理、逐工作空间授权和任务绑定。公开部署前替换本地无身份 Demo 入口，补生产数据库/迁移、TLS 和干净环境部署验证。
4. 对单 Agent 分类失败建立新的独立保留集；在真实输入与强单 Agent 质量稳固后，再比较多 Agent 的收益与成本。
