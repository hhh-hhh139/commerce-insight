# 阶段 2j · 报表差异核对

状态：确定性工具、Java/Worker、网页上传确认、历史与导出重导入已验收。当前由显式表单执行，不宣称模型已理解任意报表，也没有新增付费调用。

## 问题、选择和结果

原系统的普通指标比较会正确拒绝不同口径，但不能核查外部报告的声明金额。参考 Shopify 的销售差异说明、Stripe 的分类与日期证据、Metabase 的统一指标定义，选择结构化声明、一个授权快照重算、明确列出口径差异和剩余偏差。见 [调研和备选比较](../research/011-report-reconciliation.md)。

固定样例：已支付金额 280 元，扣除该支付批次截至指定日期的退款后为 230 元，两份正确声明的差额可由口径解释。若第二份声明为 240 元，系统保留 +10 元未解释偏差，而不是发现退款就说全部核对成功。两边同错同量也不会被误判一致；来源未知时只提供参考计算，跨币种/单位时不强行相减。

输入支持项目定义的 JSON 声明和系统导出的单指标任务，上传后预览并人工确认。报告自身的 SHA 声明不是可信签名。首版不识别任意截图、Excel 或平台导出，不重建另一个未知数据版本，不处理银行到账与结算。

套件覆盖有重叠，不将总数当成独立业务样本。工程测试包含幂等、取消、重启、无退款能力、跨空间请求、非法声明及篡改发布结果；Java 校验输入绑定和算术，不是再次运行 SQL 的独立真值源。

浏览器验收发现真实问题：网页导出格式是 `display_source/task` 包装，首次上传解析器只接受裸任务，导致自己的报告无法重新导入。保留 [失败证据](../probes/reconciliation-reimport-before-2026-11-06.json)，修复受支持包装解析后，用实际下载文件重新上传并得到 `matched`、左右均 230 元、偏差均零。其他包装不因此获得信任。

开发前源码 224 文件归档 `.local/baselines/before-report-reconciliation-20261106/source.tar.gz`，SHA-256 `98055cff7f93a30a13177a7fc048ffa56e845644b1c9e65561f7164b17a7a88a`。完成归档见 `.local/baselines/after-report-reconciliation-20261106/manifest.json`。截图与运行数据不进入源码归档。

本次无模型调用，共享预算仍为历史 65 次请求、保守占用 0.314730 元/5 元。没有真实商家试用或公网部署；原模型通过率不适用于尚未评测的新增功能。

面试可讲：报表数字不同不一定是算错；先把数据版本、指标定义与时间范围显式化，再用同一账本重算，并把能够解释的变化和仍需核查的偏差分开。真正的验收不是给出一段合理文字，而是错误声明、缺来源、两边同错和导出重导入都得到正确处理。
