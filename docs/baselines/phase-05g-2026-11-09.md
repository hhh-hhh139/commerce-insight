# 阶段 5g：容器停写备份与独立空卷恢复

日期：2026-11-09。状态：本阶段工程验收通过；完整项目仍有真实模型、公网资源和独立试用待验证项。

## 基线、调研和选择

基线为 `f238c19580f11faed761ff3d274ff9fd6bffc02e`，tree `f509c3c271ab9e51cdb7b26d6a0a39c70f42358e`。此前干净 Linux 的登录/分析/重启报告保留已经通过，但没有容器备份入口及独立卷恢复证据。真实空目录反例表明：新卷挂载根目录天然存在，原恢复函数会在读备份和访问数据库之前报 `restore_state_target_exists`。

比较 Metabase/PostgreSQL 原生逻辑备份、直接复制 Docker 卷、给业务镜像安装运维工具、独立维护容器，选择最后一种：复用已有停写锁、pg_dump/pg_restore、文件清单和指纹校验，保持业务镜像职责。仅在维护入口允许已存在但为空的状态根目录，非空目标仍拒绝。调研链接、版本、备选与预设门槛见 [研究 020](../research/020-container-recovery.md)。

## 实现和测量

应用/验收提交 `3eed114d68f70eaac6cbaae3a58b9e264e88ca0f` 已发布到唯一授权个人仓库。个人 Ubuntu 24.04 hosted runner 的[第 5 轮 CI](https://github.com/hhh-hhh139/commerce-insight/actions/runs/42584328249)本轮首次通过，验收程序耗时 **239.339 秒**，job 页面为 4m 4s。不是从点击按钮到业务恢复的 RTO，也不是性能基准。

为了让排队边界确定，测试在停止正式应用后启动临时、仅容器 loopback 可访问的真实 JVM，按相同业务 API 导入并确认样例，手动运行一次真实 Worker 完成报告，再创建待处理任务并退出 JVM。没有改写数据库行、暂停随机进程或依赖与轮询 Worker 抢时间。

维护环境实测为标准库 **Python 3.11.2 + pg_dump 18.6**；业务 Agent 仍为 Python 3.12.16。基础镜像 digest 与前一轮一致并保存到产物；系统包来自构建时官方发行源，不声称所有包已锁定为可逐字重建。完整记录见 [测量 JSON](../probes/container-recovery-2026-11-09.json)。原始 artifact SHA 为 `6c7309ba4c3095be5d22c0f94fc6b266c8e24b39f7450b473a204bf0f78af35e`，23160 字节，已下载核对。公开 artifact 保留 14 天，长期摘要和源码保留在仓库。

## 前后对照与复现

从“本机可恢复，容器只验证过重启”变为“独立维护容器可恢复到另一套空库/卷，并验证报告、任务、检查点和预算”。具体命令见 [部署手册](../deployment.md)。只在自己的部署 context 执行；个人 CI 只清理本次创建的合成测试资源，未访问公司 Docker、仓库或服务。

源码：`deployment/maintenance.py`、`deployment/compose.yaml`、`deployment/verify_container_recovery.py`、`experiments/deployment/recovery_fixture.py`。本机 CLI 保持默认不接受已有目标。维护服务不随正常应用启动，不包含模型 Key，不使用数据库管理员或 Docker socket。

## 限制和下一步

- 需要停写窗口，适用单实例；不是热备、PITR、多活或零数据丢失方案。同宿主备份卷不能覆盖磁盘丢失，需要另行私有保存离机副本。
- 恢复必须匹配备份中的精确 jar/源码/锁文件指纹，应保留原应用和维护镜像，不能假设重新构建同一 commit 的 jar 字节一定相同。
- 恢复旧备份不能冲销备份后发生的模型费用。用户本日决定暂缓核对未知调用，原累计 5 元账本保留预占；本轮真实模型调用 **0**，新付费验收不执行。
- 当前退款自然语言、上下文/专家同条件真实对照仍未完成；默认保持完整上下文单 Agent。公网域名/ACME 和独立用户价值仍没有证据，不记为已上线或已试用。

## 面试说明

“数据库恢复还不够，因为 Agent 检查点和费用账本在应用卷。我先复现空卷根目录被原恢复逻辑拒绝，再比较原生备份和直接复制卷，选择按需维护容器复用 pg_dump、状态锁及哈希清单。在个人 Linux CI 中恢复到独立空库/卷，确认旧报告不变、待处理任务只发布一次、Agent 继续而不重复工具、预算未知预占不丢。代价是需要停机，且只支持同版本单实例，不能把它讲成高可用。”
