# 数据口径最小复现实验

本实验使用项目自建的合成订单，不包含公司或商家数据。只依赖 Python 3.9 及以上标准库，在内存 SQLite 中运行，不连接网络、模型或外部数据库。

在项目根目录运行：

```sh
python3 experiments/data-metrics/reproduce.py
```

保存一次新的结果：

```sh
python3 experiments/data-metrics/reproduce.py --output .local/probes/data-metrics.json
```

## 固定条件和手工期望

金额按人民币分使用整数，时间为统一格式 UTC，区间左闭右开。样例中的订单金额代表单笔已成功收款的汇总，退款均已成功入账；不包含取消、部分支付、汇率或结算。

| 场景 | 直接关联求和 | 按金额 DISTINCT | 按订单身份去重 | 手工正确收款 |
| --- | ---: | ---: | ---: | ---: |
| A 收款 100 元有两项商品；B 收款 80 元有一项 | 280 | 180 | 180 | 180 |
| 再增加同样收款 100 元、有一项商品的 C | 380 | 180 | 280 | 280 |

按金额去重在第一组碰巧正确，第二组错误地合并了 A 和 C。按订单身份处理仅证明此样例的去重方式；不构成通用语义引擎，也不能直接推导商品分组的金额分摊。

第一组订单在 2026-10-05 至 2026-10-12 收款 180 元，退款 20 元发生在下一周。事件时间口径的两周净收退款分别为 180 元、-20 元；截至 2026-10-19，第一周付款订单的累计净收退款为 160 元。这些都不等于会计收入、利润或结算到账。

## 怎样解释结果

`fixture.json` 固定输入与事先手工定义的 9 个预期观察值。退出码 0 表示这些现象都被复现，其中包括错误 SQL 的错误结果；**不表示产品通过 9 项功能验收**。

输出保留查询、参数、实际结果、预期观察值、样例及脚本 SHA-256、Python/SQLite 版本。同一环境重复运行应产生相同 JSON；跨运行时比较数值与条件，并披露环境差异。

没有调用 LLM，不能据此评价模型成功率、自然语言理解、多 Agent 收益或产品性能。设计背景和后续组件比较见 [数据与指标研究](../../docs/research/001-data-and-metrics.md)。
